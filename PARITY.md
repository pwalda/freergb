# Feature parity with the OpenRGB app

Status: **Phase 5 (packaging) built: installers, updater, Linux device access; Phase 0 audit notes kept.** Derived from `release_1.1` source and the SDK doc, then exercised against a
real headless OpenRGB 1.1 server with fake (debug) devices on Linux (see `docs/UPSTREAM-FACTS.md`). Rows
marked **verified live** were confirmed that way; UNVERIFIED rows still need a live server or Paweł's
hardware. Nothing here has run on Windows or real RGB hardware yet.

Column key. **SDK**: YES = a packet exists and the server handles it; PARTIAL = reachable with
caveats; NO = not exposed. **Plan** uses the spec's vocabulary: DONE, SDK-LIMITED, REIMPLEMENTED
(we build it ourselves); TODO = planned, not built. "Local-only" means the server requires the
client to be loopback **and** to have requested local-client status (flag bit 16). Verified
from source: this status is **not exclusive**, so an already-running OpenRGB GUI does not block our
client, and detect-first still gets full profile/settings access when connecting over loopback.
It does mean a *remote* OpenRGB server (non-loopback) gives us no profile save/delete, no settings
writes, no logs and no device-info queries; the supervisor must treat that as a degraded mode.
